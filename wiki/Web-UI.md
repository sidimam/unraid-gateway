# Web UI

Served at `/` by the gateway itself (embedded in the binary, no external assets). Redesigned in 0.10.0; reorganised in 0.12.0 around three tabs — **Status**, **Files**, **Settings** — with the same logic as the Unraid Drive apps: the useful content first, one place for every setting, one health dot shared with the apps. Refined in 0.15.0 (collapsible cards, filters everywhere, grouped devices, focused detail views) and 0.17.0 (a **Health** page with charts, ⓘ info buttons instead of long paragraphs, user devices popup, touch-friendly column resizing).

## Header
- **Health dot** (0.12, moved to the top-right corner in 0.15): green = all fine, yellow = warnings, red = problems, grey while unknown; the short label next to it says which, hovering lists the reasons and **clicking it opens the Health page** (0.17). The same traffic light the Unraid Drive apps show next to the server name, computed by `GET /api/v1/health` (see [API reference](API-Reference#health-and-system-012)).
- After login: the user and the key's name and roles as reported by Unraid, **Forget stored key** (when a key is remembered on the gateway) and **Disconnect**. Language and theme moved to *Settings › Appearance* in 0.12.

## Login
- **Account name** + **Unraid API key**: a real form (`username` + `current-password` fields), so Safari / iCloud Keychain, Chrome and Firefox offer to save the key on the first login and fill it afterwards. The account name is only a label for your password manager (default `unraid-gateway`, freely editable — change it if you keep several gateways). Chromium browsers are also offered the credential through the Credential Management API.
- **Sign in as an Unraid user…** opens a second, optional form: Unraid user + password (saved separately by the password manager). The gateway then applies that user's share permissions exactly as over SMB; the API key is still required.
- **Remember this key on the gateway** (0.8+): stores the key in `/config/webui.key` for the one-click *Connect with the key stored on this gateway* button. Anyone who can open the page could use it — LAN or Cloudflare Access only.
- The key is validated by Unraid and exchanged for a session token kept in the tab (`sessionStorage`).

## Status (default tab)
- Four counters: **Connected now**, **Streams / transfers**, **Registered devices** (superseded entries excluded), **Gateway** version and host.
- **Activity** (0.7+, collapsible card since 0.15): connected devices (device, user, IP, since / last seen, requests, last file), streams and transfers in progress (progress bar, speed, elapsed), recent transfers. The **filter box** in the card header narrows all three tables by any text (device, user, IP, file name); refreshes every 3 s while *live* is on. A session opened with an Unraid user sees only its own rows; API-key-only and ADMIN sessions see everyone.
- Health and System information have their own **Health** page since 0.17 (the header dot is the shortcut).

## Health (0.17)
The gateway's own checks (level, reasons, *All checks*), four donut charts — checks ok / warning / error, devices by state (active today, older, not seen for 30 days, old), memory in use, shares (mounted; read/write vs read-only when an Unraid user is signed in) —, **Unraid load** over the last 24 hours or 7 days (CPU % and memory %, sampled every minute by the gateway with the key remembered for the web UI: `WEBUI_API_KEY` or *Remember this key*; kept in memory, so a restart starts a new history), **Traffic through the gateway** (bytes up/down per hour or per day and requests, every device summed, with today / 7 days / 30 days totals) and **System information**.

## Files
The root lists the mounted shares (read-only ones are marked when an Unraid user is signed in). Inside a share: **New folder**, **Upload** (with progress; one request per file, so mind proxy body limits), click a file to download, **Rename** / **Delete**. Share roots have no rename/delete: they are mount points.

Since 0.15: a **filter box** in the toolbar (matches name, date or path), **resizable columns** (drag the dividers in the header row — with a finger or the pencil too since 0.17; widths are remembered in the browser, double-tap a divider to reset) and an **Unraid path** column: the container sees `/data/<share>/…`, which on the server is the user share `/mnt/user/<share>/…` — handy when you need the path for a terminal or another container.

## Settings (everything configurable, in one place)
Order since 0.17: **Unraid API keys** (collapsible), **Notifications** (channels, *Send a test*, and since 0.18 the channel configuration form) and **For the apps** (collapsible, the apps' URL in the header) on top, then **Appearance**, **Users**, **Devices**. The explanations are behind ⓘ buttons. Opening a user or a device hides every other card: *Back* restores the page.
- **Appearance**: **Language** — *System* (follows the browser) or one of English, Italiano, Español, Français, Deutsch, 简体中文, العربية, the same seven languages as Unraid Drive (dates follow the locale, Arabic switches to right-to-left); **Theme** — *System*, *Light* or *Dark*. Both remembered in the browser.
- **Users** (0.14) — one row per Unraid user (or API key) with registered devices: devices, syncs (paused ones counted), last seen, data moved today, a warning dot. Open a user for its devices (with Remove), the folder syncs and backups of each device — a switch pauses or resumes each pair on the gateway (the app sees it at its next run), with the last run and the files it moved —, the data moved over time (all devices summed, totals and chart) and the merged log of its devices. Admins see everyone; a user sees itself. Since 0.15 the table has a **filter box** (0.17: click a user name for a popup with its devices) and the user's **log** is a collapsible section with a **device filter**, an **event filter**, an **in-log search** and **pagination** (50 rows at a time, up to 500 events). See [Users and syncs](Devices-Notifications-and-API-Keys#users-and-syncs-014).
- **Devices** (0.9+, redesigned in 0.13, grouped per Unraid user in 0.15 with a filter box; devices registered with a bare API key form the last group) — one card per Unraid Drive installation: icon by kind (iPhone, iPad, Mac, Apple TV, Vision Pro, browser), name, OS and app build, Unraid user, last sync and a state dot (green: active today; grey: older or *old*; yellow: not seen for more than 30 days). Open a card for the detail page: facts, **Data moved** (today / 7 days / 30 days totals and a chart per hour or per day over 24 h, 7, 30 or 90 days), the device **Log** (sign-ins, registration, revocation, removals, interrupted uploads, sync runs), its **syncs** (0.14, with the pause switch and file lists) and **Remove**. Below the cards: *Remove the devices not seen for N days* and **Remove all**. Superseded entries (a reinstalled app) are greyed as *old*. See [Devices, notifications and API keys](Devices-Notifications-and-API-Keys).
- **Unraid API keys** (0.9+, ADMIN key) — list, create, delete, **Rotate**.
- **Notifications** (0.9+) — the configured channels and **Send a test** in the header; since 0.18 the card opens on a form to configure the channels (Unraid notifications, e-mail, Telegram) from the browser: saved in `/config/notify.json`, applied at once, the container variables stay as defaults (*Back to the container variables* restores them). Secrets are never shown again, only marked as set.
- **For the apps** — the URL to enter in Unraid Drive (with a note on HTTPS, required by the Files app extension) and, folded away, the GraphQL proxy box.

Tables scroll horizontally inside their card on narrow windows; the last tab you used is reopened at the next login.

The UI is a convenience for testing and administration; the apps talk to the JSON API directly.
